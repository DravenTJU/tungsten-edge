# 钨极项目收尾

## 目标

在开发对话结束时，让 Obsidian 只保留当前有效的项目状态。把文档当作需要持续编辑的工作台，而不是不断追加的开发日志。

项目目录：`/Users/caye/Projects/macos-dock-cc-v2`

Obsidian 目录：`/Users/caye/Documents/Obsidian Vault/Projects/macos-dock-cc-v2`

## 事实来源

- 以本轮对话、owner 的验收反馈，以及本轮已经产生的提交、测试和工具结果为依据。
- 不重新读取、扫描或分析源代码。
- 上下文缺少分支、提交号等必要客观信息时，只核对最小范围的 Git 状态或日志。
- 上下文仍不足或相互矛盾时，不猜测、不写入文档；在结果中向 owner 说明。

## 文档职责

先阅读以下活跃文档的当前内容，再判断哪些职责确实受到本轮变化影响。没有变化的文件不要修改。

- `00 macos-dock-cc-v2 总览.md`：项目导航。只有文档结构或入口变化时更新。
- `02 当前进度.md`：当前状态、正在进行、明确的下一步、现存问题和最新检查点。改写当前内容，不追加开发流水账。
- `03 产品原则与决定.md`：当前有效产品共识的总结，不是决策日志。
  - 优先改写、合并或删除现有内容，不在末尾持续追加。
  - 同一主题只保留当前结论；决定反转后用新结论替换旧结论。
  - 只保留长期影响产品判断的原则，不记录实现细节、讨论过程、提交记录和普通小改动。
  - 新事实能归入现有原则时，归纳进原条目，不另开重复条目。
- `05 待办与想法/候选事项.md`：已经想清楚、决定保留但尚未开始的事项。事项开始实施或已经完成后，从这里移除。

## 严格边界

- 项目收尾时禁止读取或修改 `05 待办与想法/灵感速记.md`。owner 以后明确要求整理速记时，将其作为独立任务处理，不属于本 skill。
- 不修改 Archive、推广资料或个人笔记。
- 不因本流程扩写 `AGENTS.md`、`CLAUDE.md`、README 或 repo `Docs/`。
- 不创建新文档，除非 owner 明确要求改变文档结构。
- 不因为触发了 skill 就强行产生文档变更；没有新事实时直接报告无需更新。
- “收尾”不等于提交代码。只有 owner 明确说“打检查点”时，才按 `AGENTS.md` 创建本地提交；不要推送。

## 编辑与验证

1. 根据文档职责就地改写，删除已过期或重复的当前状态，避免同一事实在多个活跃文档重复维护。
2. 使用明确日期；不要用“今天”、“最近”等相对时间描述项目状态。
3. 检查被修改文档的 Obsidian 双链，确保目标文件和标题存在。
4. 确认灵感速记未被读取或修改，repo 业务代码没有因收尾流程产生额外变化。
5. 用中文简要报告改了哪些文档；没有修改时明确说明原因。
